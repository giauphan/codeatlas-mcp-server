## 2026-08-19 - [Performance improvement] Optimized O(N) array filtering with string allocations when full traversal is necessary
**Learning:** In the `manage_skills` query action, replacing `String.prototype.includes()` with `new RegExp()` inside a loop can be counterproductive and throw `ReferenceError`s if utility functions like `escapeRegExp` are not imported or defined in scope. For simple substring search where string operations like `.toLowerCase()` are applied, maintaining the use of native `.includes()` inside a manual `for` loop prevents the memory overhead of chained methods like `.filter().slice().map()` and avoids introducing bugs or unnecessary regex overhead.
**Action:** When optimizing array iterations over strings, focus on removing chained higher-order array functions that cause intermediate array allocations (like `.filter().slice().map()`). Use a single `for...of` loop with early breaks instead. Do not blindly replace native `.includes()` with `RegExp` for simple substring checks, as the regex engine has overhead and requires additional utility imports (e.g. `escapeRegExp`) which introduces a bug risk.
